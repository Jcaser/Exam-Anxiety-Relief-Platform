一、项目概述

1.1 项目背景与定位

安心考是一款面向高校学生的考试焦虑自助干预 Web 应用，以认知行为疗法（Cognitive Behavioral Therapy, CBT）为理论底座，将专业的心理自助方法转化为「随时可用、低门槛、隐私安全」的 Web 工具。项目对应传智杯命题的推荐选题第 6 条「AI 健康与生活服务 → 心理健康对话系统」，是该方向的直接落地。

当代大学生普遍面临四六级、考研、期末等高压力考试场景，考试焦虑发生率高，但传统心理咨询存在预约难、门槛高、隐私顾虑等痛点。安心考把 CBT 的七栏思维记录、认知扭曲识别、暴露练习等方法，结合大语言模型（LLM）与检索增强生成（RAG），做成可交互、可追踪的每日练习。

1.2 核心价值主张

  • 循证而非玄学：所有 AI 建议均引用 CBT 原典出处，可一键翻回书库对应章节，杜绝「编造心理建议」。
  • 本地隐私优先：心理数据默认存在浏览器本地（IndexedDB / localStorage），不出端，降低倾诉门槛。
  • 零密钥也可演示：未配置大模型 API 时自动降级为本地 RAG 抽取式作答，完整可运行、可评审。
  • 科学可量化：焦虑自评采用 8 维度随机题库，按均分科学判档，避免「全选从不仍判轻度」的错误。

1.3 技术栈总览

二、需求分析

2.1 用户痛点

痛点现状本项目回应
考试焦虑高频四六级/考研/期末季，焦虑普遍且反复自评 + 思维记录 + 对话，覆盖考前/考中/考后
专业帮助门槛高咨询预约难、费用高、 stigma免费、随时、匿名、循证的 Web 自助
泛心理 App 缺方法多靠鸡汤/打卡，无结构化方法CBT 七栏 + 认知扭曲识别，结构化干预
隐私顾虑不敢在云端倾诉敏感情绪数据本地存储，端侧优先

2.2 功能需求

  1. 焦虑自评：多维度（生理/认知/注意/睡眠/回避/自我否定/评价恐惧/反刍）、随机抽题、科学判档、历史追踪。
  2. CBT 七栏思维记录：情境→自动思维→情绪→证据→替代思维→结果，AI 引导填写，本地保存。
  3. CBT 对话陪伴：基于 RAG 的流式对话，每条建议带可点击原文引用卡。
  4. 进度可视化：情绪/焦虑分数随时间曲线，量化改变。
  5. 沉浸式首页与交互共情：全屏粒子场景 + 可点选焦虑标签的温柔回应卡片。

2.3 非功能需求

  • 性能：首屏可交互、资源按需加载；RAG 检索为本地内存计算，毫秒级。
  • 隐私与安全：敏感数据不出端；API 密钥经环境变量注入，绝不入库；危机词触发转介热线，不做医疗诊断。
  • 可用性：响应式适配桌面/移动；无大模型也能完整演示（降级策略）。
  • 可维护：组件化、TypeScript 强类型、含中文注释。

2.4 差异化

与通用心理健康助手相比，安心考聚焦「考试焦虑」这一具体、高频、可量化场景，并以CBT 原典 RAG 保证回答的循证性与可追溯性，而非泛化的聊天机器人。

三、系统架构设计

3.1 总体分层架构

① 用户与前端层   Next.js 14 (App Router) + Tailwind + 暖色玻璃拟态 UI
        │
② 核心功能模块   焦虑自评 / 智能思维记录 / CBT 对话陪伴 / 进度可视化 / 沉浸式首页
        │
③ AI 能力层      LLM 流式生成(SSE) + 双路检索(BM25+中英词表) + 安全过滤·危机兜底
        │
④ RAG 知识层     四本 CBT 原典全文(71章/4400+片段) + CBT 结构化知识卡(lib/knowledge.ts)
        │
⑤ 数据层         IndexedDB / localStorage 本地隐私存储（心理数据不出端）

3.2 前端架构

  • App Router：路由即目录，落地页 /、/assess、/record、/chat、/progress、/method 各司其职。
  • 组件化：Nav、Footer、Decor（插画/分隔）、EmpathySection（交互共情）、BreathWidget（呼吸引导）等职责单一、可复用。
  • 状态与持久化：页面级 useState + localStorage/IndexedDB，无重后端依赖。

3.3 数据流（以对话为例）

用户输入 → /api/chat（SSE）→ ① 安全过滤（危机词？）→ ② 双路 RAG 检索（原典 BM25 取 4 段 + 知识卡关键词取 2 条）→ ③ 组装带编号上下文 → ④ LLM 流式生成（要求引用 [1][2]）→ ⑤ 前端渲染思考轨迹 + 流式打字 + 可点击引用卡。

3.4 RAG 知识层结构

  • 语料构建：scripts/build_corpus.py 将四本 CBT 原典清洗 → 按章切分 → 按语义片段（≈420 字、句级重叠）切片，产出 data/library/corpus.json（71 章 / 4400+ 片段 / 约 163 万字）。
  • 检索服务：lib/rag.ts（BM25 混合检索）+ lib/library.ts（服务端加载）+ lib/knowledge.ts（CBT 知识卡）。
  • 接口：/api/kb（统计/来源）、/api/kb/search（检索 + 引用提取）。

四、AI 技术方案（重点）

本赛事「AI 技术深度」权重 35%，为最高权重维度。本节重点阐述选型理由、集成方式与优化策略，对应评分项：大模型集成(8%)、Agent/工作流(8%)、RAG(6%)、多模态(5%)、安全可控(4%)、MCP/工具(4%)。

4.1 AI 技术选型与理由

能力选型理由
大模型接入兼容 OpenAI 协议的 LLM（DeepSeek / 智谱等）生态成熟、成本低、可通过 API Routes 安全代理，密钥不暴露给前端
检索增强自研 BM25 混合检索无需外部向量库即可部署， offline 友好；针对中文做二元词切分 + 中英对照词表，命中率高
流式交互SSE（Server-Sent Events）与 Next.js API Routes 天然契合，轻量、无需 WebSocket 长连，前端逐字渲染
知识底座四本 CBT 原典全文循证来源，保证回答可追溯，杜绝编造

4.2 集成方式

  • API Routes 代理：前端不直接持密钥，所有 LLM 调用经 /api/chat 服务端代理，密钥由 .env.local 注入（已在 .gitignore 排除，附 .env.example 模板）。
  • Function Calling 降级：当未配置 LLM_API_KEY 时，系统跳过远程调用，走本地 RAG 抽取式作答（从命中片段挑选信息量最高、OCR 噪声最少的句子，配合分类动作库给建议），全程无需密钥即可完整演示。

4.3 RAG 实现细节

  • 混合检索：中文二元词（bigram）+ 英文分词；BM25 打分（k1=1.3, b=0.75）。
  • 中英对照词表：内置 50+ 组概念映射（如「灾难化→catastrophizing」），中文提问也能命中英文原版片段。
  • 章标题加权：命中章节标题的片段加权，提升相关性。
  • OCR 降噪：生僻字/错字噪声评分降低，规避错字进入引用。
  • 双路合并：原典 BM25 取最相关 4 段 + CBT 知识卡关键词取 2 条 → 编号拼接 → 模型引用 [1]–[6]。
  • 每书限量：保证引用来自多本原典，避免单源偏见。

4.4 流式输出与过程可视化

/api/chat 以 SSE 推送 trace → citations → delta → done 事件流。前端实时展示「安全检查 → 原典检索 → 组织回答」的思考轨迹与流式打字效果；回答下方渲染可点击的原文引用卡（书名/章节/摘录），一键跳回书库对应章节。对应「AI 交互体验」评分：流式渲染流畅、思考状态可视化、错误边界优雅。

4.5 安全与可控性

  • 危机兜底：内置危机识别关键词，命中即转介全国心理援助热线 12356，不给出常规建议。
  • 边界约束：所有回答限定在循证框架内，明确不做医疗诊断。
  • 内容过滤：服务端对输入/输出做安全过滤，避免有害或越界内容。

4.6 优化策略

  • 检索优化：章标题加权、每书限量、中英词表，显著提升生成质量（RAG 评分项）。
  • 降级优化：无密钥时本地抽取式作答，保证可评审、零成本演示。
  • 性能优化：RAG 语料预加载于服务端内存，检索为 O(n) 内存计算，毫秒级；前端按需加载与动画降级。

五、核心功能实现

5.1 焦虑自评（随机·多维·科学判档）

  • 8 维度 × 4 题 = 32 题：生理唤醒💓 / 认知担忧🧠 / 注意力🔍 / 睡眠🌙 / 行为回避🚪 / 自我否定🪞 / 评价恐惧👀 / 考后反刍🔁。
  • 随机抽题：每维随机抽 2 题并打乱顺序；「换一批题」重新洗牌，避免背题。
  • 科学判档：按每题均分判档——<0.5 正常 / <1.5 轻度 / <2.5 中度 / ≥2.5 高度；修复了「全选从不（0 分）仍判轻度焦虑」的科学 bug。
  • 可视化：分维度条形图配色（正常/轻度/中度/高度四色）。
  • 持久化：localStorage 存峰值与百分比，进度页可回溯。

5.2 CBT 七栏思维记录

交互式表单引导用户填写情境、自动思维、情绪强度、支持证据/反对证据、替代思维、结果。本地（IndexedDB）保存，可历史回看，契合 CBT「捕捉—辩驳—重构」的闭环。

5.3 对话陪伴与引用卡

流式 SSE 对话，模型每条建议标注 [1]–[6] 引用，前端渲染可点击引用卡，跳回 /library 对应章节，实现「说的每句话都能翻回书里」。

5.4 进度可视化

将自评分数、情绪强度随时间绘制曲线，量化「改变是否发生」，强化持续使用的正反馈。

5.5 沉浸式首页与交互共情

  • 全屏粒子场景：Canvas 实现的「雨 + 余烬 + CBT 徽章」沉浸式 hero，暖色调与全站统一。
  • 可点选共情区块（EmpathySection）：四个考前焦虑标签可点选，展开「内心独白 → AI 温柔回应 → CBT 知识点 → 行动按钮」，配 Framer Motion 入场/切换动画。对应「前端交互体验」「UI 视觉」评分项。

七、创新点说明

7.1 技术创新

  • 零向量库 RAG：自研 BM25 混合检索（中文二元词 + 中英对照词表 + 章标题加权 + OCR 降噪），不依赖任何外部向量库即可部署，离线可用、成本低。
  • 可追溯生成：AI 每条建议带可点击原文出处，把「黑盒生成」变为「循证引用」，解决心理健康场景的可信度问题。
  • 双路检索 + 安全降级：原典检索与知识卡双路合并；无密钥时本地抽取式作答，兼顾深度与可用性。
  • 危机兜底机制：关键词触发热线转介，体现「负责任 AI」的设计理念（对应 AI 安全与可控性评分项）。

7.2 应用创新

  • 选题聚焦：锁定「考试焦虑」这一具体、高频、可量化场景，而非宽泛的心理健康助手。
  • 方法产品化：把 CBT 七栏思维记录做成可交互、可追踪的 Web 工具，并用 AI 引导填写。
  • 交互模式创新：全屏粒子沉浸式 hero + 可点选共情回应卡片，把「安抚情绪」本身做成可玩的交互体验。
  • 隐私创新：端侧本地存储优先，降低倾诉门槛，呼应数据安全与合规要求。

八、总结与展望

安心考以 CBT 为理论底座、以 RAG 为可信引擎，把专业的考试焦虑自助方法做成随时可用、隐私安全、循证可追溯的 Web 应用。项目在「AI 技术深度（35%）」上以自研 RAG、LLM 流式集成、安全降级与危机兜底形成闭环；在「创新性（25%）」上以聚焦场景、可追溯生成、交互模式创新体现差异；在「前端工程质量 / 用户体验 / 实用性 / 社会价值」各维度均有扎实落地。

未来展望

  • Agent 工作流：引入具备规划与工具调用的 CBT 引导 Agent（对应 Agent/工作流 8% 评分项）。
  • 多模态：加入语音安抚、情绪识别等模态（对应多模态 5% 评分项）。
  • MCP/工具集成：通过 Function Calling / MCP 接入日历、提醒等外部工具（对应 MCP 4% 评分项）。
  • 个性化：基于长期记录做自适应干预路径，提升实用性与留存。
